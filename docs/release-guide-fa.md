# راهنمای انتشار واژه‌سفر — مایکت / کافه‌بازار + پرداخت درون‌برنامه‌ای + تبلیغات

این سند دقیقاً می‌گوید برای **انتشار**، **فعال‌سازی پرداخت درون‌برنامه‌ای (IAP)** و **فعال‌سازی تبلیغات** چه کارهایی لازم است.
وضعیت فعلی کد (v1.17) **کاملاً آمادهٔ انتشار** است: هیچ حالت نمایشی‌ای باقی نمانده، تبلیغات خاموش است و خریدها فقط از طریق پل واقعی فروشگاه انجام می‌شوند.

---

## ۱) چه چیزهایی از قبل آماده شده (بک‌اند بازی)

| بخش | وضعیت | توضیح |
|---|---|---|
| حالت نمایشی خرید | ❌ حذف شد | بدون پل پرداخت، هیچ سکه‌ای داده نمی‌شود؛ فقط پیام «پس از انتشار فعال می‌شود» |
| تبلیغات | ⛔ خاموش (`ADS_ENABLED = false`) | تب «سکهٔ رایگان» و هر رابط تبلیغ از رابط کاربری حذف شده |
| شناسهٔ محصولات | ✅ آماده | `coins_50` ، `coins_250` ، `coins_550` ، `coins_1200` ، `golden_bundle` ، `remove_ads` |
| پل بومی (Bridge) | ✅ قرارداد مشخص | `window.VzBilling` و `window.VzAds` — قرارداد JSON در `src/game/core/monetization.ts` |

- قرارداد پرداخت/تبلیغ: `src/game/core/monetization.ts`

- تنظیمات اندروید: `android/app/build.gradle` (نسخه)، `AndroidManifest.xml` (مجوزها)

## ۲) انتشار در کافه‌بازار و مایکت — قدم به قدم

### قدم ۱ — ساخت حساب توسعه‌دهنده
- **کافه‌بازار**: پنل توسعه‌دهندگان `developers.cafebazaar.ir` → ثبت‌نام با مدارک هویتی → پرداخت هزینهٔ ثبت پنل.
- **مایکت**: پنل `developer.myket.ir` → ثبت‌نام و احراز هویت.
- هر دو شماره شبا/کد اقتصادی برای تسویه درآمد IAP می‌خواهند.

### قدم ۲ — ساخت Keystore امضا (مهم‌ترین کار؛ فقط یک‌بار)
امنیت و به‌روزرسانی اپ به این فایل وابسته است؛ **گم شدنش یعنی از دست رفتن اپ**. روی سیستم خودتان:

```bash
keytool -genkey -v -keystore vazhesafar-release.keystore -alias vazhesafar \
  -keyalg RSA -keysize 2048 -validity 10000
```

سپس در `android/app/build.gradle` به‌جای keystore فعلی (که برای تست است) اضافه کنید:

```gradle
signingConfigs {
    release {
        storeFile file('vazhesafar-release.keystore')
        storePassword 'رمز Keystone'
        keyAlias 'vazhesafar'
        keyPassword 'رمز Key'
    }
}
buildTypes {
    release {
        signingConfig signingConfigs.release
        ...
    }
}
```

⚠️ فایل keystore را هرگز به گیت پاس ندهید (در `.gitignore` بگذارید) و از آن نسخهٔ پشتیبان امن نگه دارید.
تا وقتی keystore اختصاصی نساخته‌اید، CI با keystore تست امضا می‌کند — برای نصب محلی مشکلی نیست، اما برای انتشار نهایی حتماً keystore شخصی بسازید.

### قدم ۳ — پر کردن پنل فروشگاه
برای هر دو فروشگاه این‌ها را آماده کنید:
- **نام پکیج**: `ir.vazhesafar.game` (در `android/app/build.gradle`)
- **توضیح کوتاه/بلند فارسی** + دستهٔ «کلمات و پازل»
- **اسکرین‌شات**: حداقل ۲ و حداکثر ۸ تصویر (پیشنهاد: صفحهٔ اصلی، داخل بازی، چرخ حروف، نقشه، فروشگاه، بازی دورهمی) — 1080×1920
- **آیکون ۵۱۲×۵۱۲** (از `public/icon-512.png` — همین تازه‌ساخته را بدهید)
- **تصویر شاخص/بنر** (بازار: 1024×500)
- **سیاست حفظ حریم خصوصی**: یک صفحهٔ وب ساده بسازید (می‌تواند یک GitHub Pages باشد) و آدرسش را وارد کنید؛ محتوای پیشنهادی: «بازی هیچ داده‌ای به سرور ارسال نمی‌کند؛ پیشرفت بازی فقط روی خود گوشی ذخیره می‌شود.» (همین متن در بخش «درباره → حریم خصوصی» داخل بازی هم هست.)
- **ردهٔ سنی**: Everyone / همهٔ سنین (بدون خشونت، بدون چت آنلاین)
- **سیاست داده (Data Safety)**: هیچ داده‌ای جمع نمی‌شود؛ اگر بعداً تبلیغات AdMob/Tapsell فعال شد، باید «شناسهٔ تبلیغاتی جمع می‌شود» را اضافه کنید.

### قدم ۴ — بررسی امنیتی که انجام شده (برای فرم‌های بررسی)
- مجوزها: فقط `INTERNET` ✅
- بدون `android:debuggable`، بدون ترافیک HTTP غیرامن ✅
- بدون جمع‌آوری داده، بدون شبکهٔ خارجی، همهٔ دارایی‌ها لوکال ✅
- محتوای واژگان فارسی پاک‌سازی‌شده (اسکریپت `scripts/validate_words.ts`) ✅
- نسخه: `versionCode 3` / `versionName 1.17.0` — هر انتشار بعدی `versionCode` را +۱ کنید.

### قدم ۵ — ساخت APK نهایی و آپلود
با تگ گیت‌هاب هر دو APK ساخته می‌شوند:

```bash
git tag v1.17.0
git push origin v1.17.0
```

از صفحهٔ Releases گیت‌هاب، `VazheSafar-v*.apk` را دانلود و در پنل فروشگاه آپلود کنید.
(فایل `VazheSafar-AllLevels-v*.apk` فقط برای تست خودتان است — هرگز آن را آپلود نکنید.)

## ۳) فعال‌سازی پرداخت درون‌برنامه‌ای (بعد از تأیید در پنل)

### کافه‌بازار → کتابخانهٔ Poolakey
1. در پنل بازار → «درآمد → پرداخت درون‌برنامه‌ای» همهٔ ۶ محصول را با **همان شناسه‌های جدول بالا** بسازید (نوع: مصرف‌شدنی برای سکه‌ها، غیرمصرفی برای `remove_ads`).
2. در پروژهٔ اندروید یک پلاگین کوچک Capacitor بسازید (جاوا) که Poolakey را صدا بزند و نتیجه را با این قرارداد به جاوااسکریپت بدهد:

```java
// مثال ساده‌شده داخل پلاگین
@CapacitorPlugin(name = "VzBilling")
public class VzBillingPlugin extends Plugin {
  @PluginMethod
  public void purchase(PluginCall call) {
    String productId = call.getString("productId");
    // → Poolakey.purchaseProduct(...) با bazaar verification
    // موفق:
    JSObject ret = new JSObject(); ret.put("ok", true); ret.put("orderId", order.getId());
    call.resolve(ret);
    // ناموفق:
    // ret.put("ok", false); ret.put("error", "پیام خطا"); call.resolve(ret);
  }
}
```

3. همین و بس — سمت جاوااسکریپت از قبل آماده است؛ وقتی `window.VzBilling` وجود داشته باشد خرید واقعی می‌شود، وگرنه پیام «پس از انتشار فعال می‌شود» نشان داده می‌شود. **هیچ خرید تقلبی‌ای وجود ندارد.**

### مایکت → In-App Billing مایکت
همان کار با SDK مایکت (`com.myket.android.billing`). اگر می‌خواهید روی هر دو فروشگاه انتشار دهید، دو وریانت بیلد با `flavor` بسازید یا شناسهٔ فروشگاه را در زمان اجرا تشخیص دهید (`installer` پکیج) و SDK متناظر را صدا بزنید.

### تست IAP
- بازار: حساب تست (licensed tester) در پنل اضافه کنید.
- هر دو: اول با محصول ارزان (`coins_50`) مسیر خرید→تأیید→سکه را تست کنید.

## ۴) فعال‌سازی تبلیغات (بعداً، وقتی خواستید)

الان `ADS_ENABLED = false` است و همه‌چیز تبلیغاتی از UI حذف شده. وقتی آماده بودید:

1. شبکهٔ تبلیغاتی را انتخاب کنید (پیشنهاد برای ایران: **تپسل** / تپسل پلاس؛ جهانی: AdMob).
2. SDK را داخل همان پلاگین Capacitor به‌صورت `VzAds` بدهید:

```java
@CapacitorPlugin(name = "VzAds")
public class VzAdsPlugin extends Plugin {
  @PluginMethod
  public void showRewarded(PluginCall call) {
    // → Tapsell.showAd(...) ; onComplete:
    JSObject ret = new JSObject(); ret.put("completed", true); call.resolve(ret);
  }
}
```

3. در `src/game/core/monetization.ts` مقدار `ADS_ENABLED` را `true` کنید و publish کنید.
4. تب «سکهٔ رایگان» و جایزهٔ `REWARDED_COINS` خودکار برمی‌گردند؛ برای خریداران «حذف تبلیغات» (`Save.data.adsRemoved`) هیچ تبلیغی نشان داده نمی‌شود.
5. اگر AdMob فعال می‌کنید، در Data Safety فروشگاه «شناسهٔ تبلیغاتی» را اعلام کنید و مجوز `AD_ID` را به منیفست اضافه کنید.
